# 職務経歴書の評価基準

`resume-review` skillのレビュアーと、人手での見直しが共通で使うルーブリックである。
指摘は必ず下記のID(例: `C2`)を付けて出す。

## 良い職務経歴書の定義

狙ったポジションの読み手に、短時間で「この人に会いたい」と判断させ、面接の話題を自分に有利な方向へ導ける文書。
文書の出来そのものではなく、この目的を果たせるかどうかで評価する。

## A. 戦略:誰に何を売るか

| ID | 観点 | 問い |
| --- | --- | --- |
| A1 | ターゲット | 狙う職種・企業像を1文で言えるか。経歴と志向・NG条件が矛盾していないか |
| A2 | 能力レベルからの逆算 | 狙うレベルで期待される能力を先に定め、それを示すエピソードを選んでいるか |
| A3 | 前向きな志向 | 経歴の流れが「次にこれをやりたい」につながっているか。逃げではなく、伸ばす方向として読めるか |

## B. 構成:全体の流れ

| ID | 観点 | 問い |
| --- | --- | --- |
| B1 | 30秒テスト | 冒頭だけを読んだ人が、強みを正しく言い当てられるか |
| B2 | 役割が変わるタイミング | 役割・責任範囲が広がった時点と、そのきっかけ(指名か自発か)が読み取れるか |
| B3 | ノイズ | ターゲットの判断に寄与しない記述が、重要な記述を埋もれさせていないか |
| B4 | サマリと詳細の整合 | README.mdとdetail.mdで事実・時期・体制・表現が食い違っていないか |

## C. エピソード:各実績の書き方

| ID | 観点 | 問い |
| --- | --- | --- |
| C1 | 三段構成 | 状況 → 行動と判断 → 成果 の三段がそろっているか。とくに成果が欠けていないか |
| C2 | why / why not | なぜその手段を選び、なぜ他の選択肢を選ばなかったかが書かれているか |
| C3 | 会社の判断と自分の判断 | 組織の決定と、本人の判断・提案が区別され、主体性が見えるか |
| C4 | 数字 | 規模・改善幅・期間・頻度などが定量化されているか |
| C5 | 具体性 | 同じ職種の他の候補者に入れ替えても成り立つ文になっていないか |
| C6 | ユーザーの一次情報 | 顧客・利用者と直接の接点を持ち、そこで得た情報を判断に使ったことが書かれているか |
| C7 | 未経験への向き合い方 | 未知の技術・課題をどう立ち上げて成果につなげたか(再現性のある学び方)が書かれているか |
| C8 | 面接での耐久性 | 深掘りされたとき、一次情報で答えられる内容か。根拠の薄い主張・盛りに見える箇所がないか |

## D. トーン

| ID | 観点 | 問い |
| --- | --- | --- |
| D1 | 他罰的でない | 課題を人や組織のせいにせず、客観的な状況説明として書けているか |

## E. 公開リポジトリの制約

| ID | 観点 | 問い |
| --- | --- | --- |
| E1 | 公開してよい情報か | 退職理由の内情・報酬・取引先名・開示できない社内数値が書かれていないか |

退職理由はこのリポジトリに書かない。経歴書では「次にやりたいこと」として表現する。
