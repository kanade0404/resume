# 出力形式

## ペルソナの出力

最初に、あなたの立場から見た**総合判断を1〜2文**で書く(例: 「書類選考は通すが、面接で〜を必ず聞く」)。
続けて、指摘を1件ずつ次の形式で並べる。重要な順に並べ、最大10件とする。

```yaml
- rubric: [C2]            # ルーブリックのID。複数可
  severity: Major         # Critical / Major / Minor
  location: detail.md:144 # path:line
  quote: "マルチテナントのSaaSとして設計し"  # 対象ファイルからの完全一致の引用
  issue: 何が足りないか、何が問題か(1〜2文)
  reader_impact: あなたの立場で、それが判断にどう影響するか(1文)
  fix: 直し方の提案(1〜2文)
  needs_user_input: yes   # 直すのに本人しか知らない情報が必要なら yes
  question: 本人に聞くべき問い(needs_user_input が yes のときのみ)
```

severityの基準:

- Critical: この箇所のせいで、選考で落とされる・誤解される可能性が高い
- Major: 評価を明確に下げる、または強みを伝え損ねている
- Minor: 直せば読みやすくなる程度

最後に「良い点」を1〜3件、引用付きで書く。

守ること:

- 引用は対象ファイルの文字列と完全に一致させる。言い換えない
- 書かれていないことを推測で補って指摘しない。判断できなければ「判断不能」として理由を書く
- 担当外の観点でも重大なものは指摘してよいが、担当IDを優先する

## 統合の出力

```markdown
## 総合判断
<ペルソナごとの総合判断を1行ずつ>

## 指摘(優先度順)
### 1. <見出し> [C2][C6] Critical — screener, business
- 場所: detail.md:132-154
- 引用: "..."
- 問題: ...
- 直し方: ...
- 本人への問い: ...(needs_user_input のときのみ)

## ペルソナ間の対立
<読み手によって望む方向が逆の指摘。解消せず、トレードオフとREADME/detailのどちらに置くかの判断材料として示す>

## 却下した指摘
<引用が実在しない、事実誤認などで捨てたもの。1行ずつ理由を付ける>

## 良い点
<引用付きで1〜3件>
```
