# Phase 3: 組織・人

**扱うのは職業上の経歴だけ。** 私生活・家族・健康・SNS の私的投稿は、公開されていても収集しない。
個人名は Notion/Obsidian(private)にだけ書き、この repo には書かない。社員DB には書き込まない。

分担の目安: 3-A・3-E を 1 subagent、3-B・3-C を 1 subagent、3-D を 1 subagent(いずれも sonnet)。
出力は `<scratchpad>/30-<観点>.md`。

## 3-A 主要エンジニア/リーダーの離職

- 歴代 CTO / VPoE / EM / テックリードの一覧と在任期間(役員紹介の過去版、登壇資料の肩書き、インタビュー)
- 退職エントリ(個人ブログ・note・Zenn で「退職」「卒業」+社名)
- 過去の発信者(テックブログ・登壇)の**現所属**(現在のプロフィールで確認できるもの)
- 結論は「確認できた離職」「在籍確認できた」「未確認」の3区分。**確認できない ≠ 離職がない**

## 3-B 経営陣・部長層の出身母体

- 役員・部長層の前職を一覧化し、特定企業(同じ出身母体)の層別比率を出す
  (例: 役員5名中3名が同じ前職。経営陣/部長層/リーダー層で分けて数える)
- 出身母体の偏りがある場合、文化・意思決定への影響の**仮説**を書く(推測と明記)

## 3-C エンジニアの前職分類

公開プロフィール(採用ページの社員紹介、登壇資料、テックブログの著者紹介、公開職歴)から分類する。

| 分類 | 例 |
|---|---|
| 大企業 | 大手事業会社・大手通信・大手金融の社内開発 |
| メガベンチャー | 大規模 Web 企業 |
| SIer・SES・受託 | システムインテグレーター、受託開発 |
| スタートアップ・中小 Web | 創業期〜中規模の Web 企業 |
| その他 | 研究職、異業種からの転身など |

- **入社時期別**(創業期/直近2年など)に集計し、構成の変化を見る
- SIer 出身者がリーダー・アーキテクト層にいるかを分けて数える(層によって意味が変わるため)
- サンプル数と、どこから拾ったか(サンプリングの偏り)を必ず書く

## 3-D 営業主導 / エンジニア尊重の証拠

**両側**の証拠を集める。片側だけ集めて結論を出さない。

| 営業主導の兆候 | エンジニア尊重の兆候 |
|---|---|
| 受託的な個社対応の多さ、ロードマップが商談起点 | 技術投資・リファクタリングの記事、開発者体験への投資 |
| 経営陣・取締役会に技術代表がいない | CTO が取締役、技術判断の権限が明記されている |
| エンジニアの評価制度が営業成果連動 | エンジニアのキャリアラダー・技術職の上位等級 |

- CTO の役職変遷(取締役 CTO → 執行役員 → 退任 などの推移)と、取締役会に技術の代表がいるか

## 3-E 口コミ

- 口コミサイト(OpenWork 等)の傾向は**二次情報**。件数・投稿時期・職種の偏りを添える
- 個別投稿の引用は最小限。個人が特定できる記述は転記しない
