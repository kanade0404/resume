# Notion DB スキーマ(列名と意味)

ID・URL は設定ファイル(`research-config.local`)から取る。ここには列名と型、選択肢だけを書く。
書き込み前に毎回 `notion-fetch` で data source を取得し、列名・選択肢が下表と一致するか確認する
(ユーザーが Notion 側で列を変えている可能性がある。差異があれば Notion 側を正とし、ユーザーに報告する)。

## 企業DB

| 列 | 型 | 意味・書き方 |
|---|---|---|
| Name | title | 正式社名(株式会社等を含む表記はDB既存レコードに合わせる) |
| URL | url | 公式サイト |
| 事業内容 | text | 主力事業の1〜2文 |
| 要約 | text | 調査結論の要約(3〜5文。投資家目線・組織の要点を含める。機微情報は書かない) |
| 創業日 | date | 設立日。出典は登記・会社概要 |
| 従業員数 | number | 最新の公表値。出典と時点を本文に書く |
| 旧Tags | multi_select | **廃止予定。新規に書き込まない**(分類は事業DBの対象業界・機能領域・事業モデルで行う)。既存値の閲覧のみ |
| 資本状況 | select | 上場 / 上場企業子会社 / VC出資 / 自己資本・非上場方針 / 不明 / 事業会社出資・合弁 / PE出資。判定基準は下記「資本状況の判定」 |
| 事業 | relation → 事業DB | 事業DB側の「企業」を設定すると双方向で付く |
| 対象業界(事業) / 機能領域(事業) / 事業モデル(事業) | rollup | 事業 relation 経由、show_unique。**読み取り専用** |
| Status | status | Queued / In-Progress / Error / Done。調査開始で In-Progress、書き込み完了で Done、途中断念で Error |
| 志望度 | select | 判定中 / 高 / 中 / 低。**本 skill は変更しない**(ユーザーが決める) |
| 英語利用 | checkbox | 社内公用語・業務で英語を使う証拠があれば true |
| 業界 | relation → 業界DB | 該当する業界レコード。**1社に複数可**(多事業の会社がある) |
| 外部発信 | relation → 外部発信DB | 外部発信DB側の「企業」を設定すると双方向で付く |
| 技術スタック | relation → 技術スタックDB | 既存レコードがあれば紐付けのみ。新規作成は範囲外 |
| 社員 | relation → 社員DB | **書き込まない**(個人の記録を増やさない) |
| 会社の設立からの年数 | formula | 読み取り専用 |

### 資本状況の判定

- 上場: 本体が上場(上場子会社でも本体が上場ならこちら)
- 上場企業子会社: 上場企業が過半数を保有(孫会社を含む)
- 事業会社出資・合弁: 単独の上場親会社がない共同出資、または非上場事業会社の子会社
- PE出資: PEファンドが支配株主
- VC出資: VC・CVC から株式を調達したスタートアップ
- 自己資本・非上場方針: 外部株主がいない、または創業者・従業員以外の株主がいない状態で非上場を明言(VC・PE・事業会社の出資を受けている場合は、非上場方針を明言していても該当する出資区分を優先する)
- 不明: 上記を判定できる出典がない

## 事業DB

1行 = 1プロダクトまたは1事業ライン。

| 列 | 型 | 意味・書き方 |
|---|---|---|
| 事業名 | title | プロダクト名または事業ライン名 |
| 企業 | relation → 企業DB | 所属企業(双方向。企業DB側の列名は「事業」) |
| 業界 | relation → 業界DB | 企業の業界 relation がその事業に合う場合だけ設定 |
| 対象業界 | multi_select | 業界横断, 建設, 不動産, 医療, 介護, 物流, 製造, 小売・EC, 飲食・食品卸, 金融, 保険, 教育, エネルギー, モビリティ, 公共・自治体, 人材, 旅行, 法律, 広告・メディア, 個人消費者, 農業, 警備, スポーツ・フィットネス, エンタメ・ゲーム, 製薬, 福祉・障害者支援, 保育, 通信 |
| 機能領域 | multi_select | 経理・財務, 経営管理・予実, HR・労務, 採用, 営業, マーケティング, CS・顧客対応, 受発注・調達, IT管理・セキュリティ, 業務自動化, サステナビリティ, 法務, 現場業務・施工管理, 設計・データ管理, 資金調達・与信, 学習, 新規事業開発, 業界特化業務, 開発・エンジニアリング, 決済・金融サービス, 資産・設備管理, 仲介・リーシング, 価格査定・審査, コミュニケーション・コラボレーション, 計画・最適化, EC・店舗運営, 業務標準化・マニュアル |
| 事業モデル | multi_select | SaaS, マーケットプレイス・マッチング, BPO・役務, 金融サービス, コンシューマーアプリ, 受託開発・コンサル, ハードウェア・IoT, 物販・卸・D2C, AI基盤・API, 広告, メディア・コンテンツ配信, 不動産開発・運営, 人材紹介・派遣, インフラ運営, 医療機器・SaMD |
| 顧客 | multi_select | 大企業, 中堅・中小, 個人, 公共・自治体, 医療機関・施設, 教育機関, 製薬 |
| 主力 | checkbox | 1社に最低1つ true にする |
| 説明 | text | 事業の説明 |
| 規模メモ | text | 売上・ユーザー数などの規模(出典と時点を添える) |
| URL | url | プロダクトのURL |

### 判定ルール

1. 1社あたり1〜3行が目安。主力は最低1つ。調査本文に根拠がない小さな事業は行にしない
2. 「医療のHR」(医療機関向けHR SaaS)は1行で、対象業界=医療、機能領域=HR・労務。
   「医療事業とHR事業を別々に持つ」は2行で、(医療, 業界特化業務) と (業界横断, HR・労務)
3. 業界を問わず売る製品は、対象業界=業界横断。主要顧客の業界が明確なら併記してよい
4. 機能領域「業界特化業務」は、他の選択肢のどれにも当たらない業界固有の業務に限る
   (例: 遠隔画像診断、介護オンコール、受診勧奨、WMS)
5. 個人向けコンシューマーアプリは、学習など明確な機能がなければ機能領域を空にする
6. グループ内向けの開発子会社は、顧客=空、対象業界=親グループの業界、事業モデル=受託開発・コンサル
7. 業界 relation は、企業の業界 relation がその事業に合う場合だけ設定する

## 業界DB

| 列 | 型 | 意味・書き方 |
|---|---|---|
| Name | title | 業界名(既存レコードの粒度に合わせる) |
| 企業 | relation → 企業DB | 調査済み企業を紐付け |

| 日米スタートアップの違い | text | 比較表の要点を3〜5行 |
| 調査日 | date | 調査を行った日 |
| Status | select | 調査中 / 完了 |

## 外部発信DB

| 列 | 型 | 意味・書き方 |
|---|---|---|
| タイトル | title | 記事タイトル(原文のまま) |
| URL | url | 正規化した記事URL(重複チェックのキー) |
| 企業 | relation → 企業DB | 対象企業。**必ず設定**する |
| 媒体 | select | note / テックブログ / SpeakerDeck / PR TIMES / インタビュー記事 / Podcast・動画 / X / その他 |
| 発信者区分 | select | 公式 / 経営陣 / 社員 / 第三者メディア(判定基準は `external-publications.md`) |

| 著者 | text | 署名者。役職は記事時点のもの |
| 公開日 | date | 記事の公開日 |

| サマリ | text | 本文全文を読んだうえでの要約(3〜5文) |

## 書き込みの共通ルール

- Notion 本文ではパイプ表(`| a | b |`)が崩れるため `<table>` 記法を使う
- 既存ページ本文は**変更しない**。差し込みは `notion-update-page` の `update_content` で行う
  (`old_str` = 既存の見出しなど一意なアンカー、`new_str` = 同じアンカー + 追加セクション。アンカー自体の文言は変えない)。
  末尾追記だけなら `insert_content`(`position: end`)。全文置換の `replace_content` は使わない。
  挿入前後で本文を fetch し、追加部分を除いた既存部分のハッシュ/diff が一致することを確認する
- `URL` 列はツール上 `userDefined:URL` と書く。日付は `date:<列名>:start` 形式
- プロパティ更新(`update_properties`)は対象列だけを指定する(他の列を空で上書きしない)
- Notion MCP で multi_select の選択肢を改名すると、既存の値が消える(delete + add 扱いになる)。
  改名する前に全行の値を退避し、改名後に新しい名前で書き戻すこと
