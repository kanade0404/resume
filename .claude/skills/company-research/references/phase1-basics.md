# Phase 1: 基本調査(観点ごとに並列)

4観点を並列 subagent(sonnet)で調べる。各 subagent は `00-identity.md` と `01-seed-urls.md` と
`search-log.md` を最初に読む。出力は `<scratchpad>/10-<観点>.md`。

## 評価スケール(4観点共通)

各観点の末尾に5段階評価と根拠を付ける。評価だけで根拠が無いものは書かない。

| 評価 | 意味 |
|---|---|
| 5 | 同規模の会社の中で明確に優れている(具体的証拠が複数) |
| 4 | 優れている点が具体的に確認できる |
| 3 | 平均的/判断材料が半々 |
| 2 | 弱い点が具体的に確認できる |
| 1 | 重大な懸念がある(具体的証拠付き) |
| 判定不能 | 材料不足。何が足りないかを書く |

## 1-A 事業

- プロダクト一覧(対象顧客、提供形態、価格帯)
- KPI 推移(導入社数・ARR・GMV・取扱高・継続率など、公表されているものを時系列で。**出典の日付ごとに**)
- 資金調達(ラウンド・日付・額・リード投資家)。詳細な資本構成は Phase 2 で扱う
- 提携・M&A・子会社
- AI の活用(プロダクト機能か社内業務か、発表のみか提供済みか)
- 競合と差別化(会社の主張と、第三者から見た差の両方)
- 強み/リスク(各3つまで、根拠付き)

## 1-B 開発発信

- テックブログの更新頻度(直近12か月の記事数)、執筆者数、技術領域
- 登壇(SpeakerDeck、connpass、カンファレンス)、OSS(GitHub org のリポジトリ数・更新)
- 技術スタック(採用ページ・ブログ・登壇資料から。出典ごとに)
- 開発組織の構成・規模の記述

## 1-C 事業発信

- プレスリリースの頻度と内容の傾向(提携・導入事例・調達・受賞の比率)
- 経営陣のインタビュー・note の主張(詳細な取り込みは Phase 4)
- 主張の一貫性(年ごとに言っていることが変わっていないか)

## 1-D 採用活動

- 掲載媒体(HERP / Green / Wantedly / Forkwell / 自社)と募集職種の一覧・件数
- エンジニア職の募集内容(求める経験、技術スタック、チーム構成の記述)
- 上場準備系ポジション(内部監査・IR・経理・法務)の有無 → Phase 2 の IPO 準備度に渡す
- 給与レンジは**記録しない**(この公開 repo の skill から出す成果物にも、要約にも載せない。必要ならユーザーが private 側で扱う)

## main の統合

4ファイルを読み、観点間の矛盾(例: 事業発信では急成長、採用では募集が急減)を `<scratchpad>/19-phase1-notes.md` に
書き出し、Phase 2/3 の subagent に「確認すべき論点」として渡す。
